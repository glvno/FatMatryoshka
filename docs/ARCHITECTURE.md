# Architecture and plan

## Goal

Patch a small modular synth in the browser, run it on an M-VAVE FM-1. No FM engine, sampler, sequencer or UI from Felucca: only its flashing path and its hardware layer.

## What the FM-1 is (as far as known)

From the Felucca and FM-1 reverse-engineering projects: a JieLi AC791N SoC (pi32v2 core), 240×240 colour LCD, 27 keys, 7 knobs plus volume, USB MIDI/audio, TRS MIDI in, battery. CPU clock, RAM and flash sizes are **not verified** here; Felucca's `firmware/app.ld` and `tools/build.py` hold the memory map (app slot 0x8DFBC bytes, app RAM + a pool region).

## Flash path (reused from Felucca)

1. Browser (or `tools/fm1_install.py`) talks SysEx over USB MIDI. The *device* asks for blocks of a "logical image" (the package minus 20 marker bytes) and the host answers.
2. Step 1: the running firmware verifies parts of the package and stages Felucca's update loader. Step 2: the loader reads the whole package and writes flash. Then the device restarts and the identity (`FM-1_<n>`) is checked.
3. A package is built by `tools/fm1pkg_make.py` / `tools/build.py` (app.bin + loader ota.bin + three JieLi SDK files). The browser can also patch an app.bin into the user's own official V15 (`buildFeluccaPackage`).

## Patch engine

`web/src/engine.ts` and `web/src/modules.ts` are the reference implementation: float DSP, 128-frame blocks, patch graph ordered by `processingOrder` (loops become one-block feedback). Module definitions (`ModuleDef`) are data and are shared by the editor and, later, the firmware.

## Firmware

Builds with `tools/build.py` inside `nix develop` (see CLAUDE.md), flashes with the web flasher or `tools/fm1_install.py`.

- `firmware/src/engine.c` is the fixed-point port of `web/src/engine.ts` and `modules.ts` (all 13 modules, mono voice, CV inputs, feedback cables as one block of delay). Signals and parameters are Q16.16, oscillator phase u32, filter coefficients Q24, envelope Q30; sine, exp2 and tan come from tables (`tools/gen_dsp_tables.py` -> `dsp_tables.h`). No float anywhere. The 32x32->64 multiply and the 32-bit divide are hardware; 64-bit division (a libcall) is used only at block rate and on waveform edges.
- `firmware/src/defs.h` and `presets.h` are generated from the TypeScript definitions (`npm run export-defs` in `web/`): module/port/parameter indices and the factory patches in the binary format of `web/src/patchbin.ts`. Port and type indices are append-only.
- The audio ISR (`audio.c`) renders 128 frames per half buffer. MIDI program change selects a factory patch, note on/off and CC 123 drive the voice. The LCD shows the patch name in the top bar; the measured CPU load (ISR time per half buffer, key scan and USB nested in it) is kept in `eng_us_last` / `eng_us_max` but no longer drawn.
- `tools/golden.sh` renders 11 patches with the TypeScript engine and the C engine (host build) and compares them. Smooth patches agree to about 0.1 % rms (-60 dB), patches with saw/square edges to 1-2 % rms: the Q16 pitch grid moves an edge by a fraction of a sample, which gives short spikes at the edges and no audible difference.
- Memory: see "Voices and the shared pools" below. The one-voice build (the default, `ENG_VOICES` 1): one engine, 255 signal buffers (128 KB), 128 instances, one delay line of 521 ms (46 KB), one reverb, eight strings, a chorus and a granular line (88 KB), about 391 KB of the 418 KB pool (stand-in estimate, 27 KB free). The four-voice build (`-DENG_VOICES=4`): four engines, 108 buffers, 72 instances, four delays, two reverbs, six strings, no granular line, about 409 KB. Limits per voice are 32 modules and 192 cables in both.

Measured on the FM-1: the 303 Acid factory patch (8 modules, one delay) uses 11 % of the audio budget (peak 12 %).

Patch transfer (M1-0.3): `web/src/protocol.ts` defines the SysEx messages (`F0 7D 4D 31 cmd payload F7`, payload packed to 7 bit): HELLO/INFO, patch upload in 384-byte CHUNKs with an ACK each, COMMIT with a CRC-16, STORE, live PARAM. `firmware/src/proto.c` implements it (host-tested bit-exactly by `firmware/test/proto_test.c` through `tools/golden.sh`), `patchstore.c` keeps the patch in two A/B flash sectors (0x97000, 0x98000) and the firmware boots the stored patch, else factory patch 0. A failed commit leaves the previous patch running; STORE saves the live-edited parameters too. `web/src/device.ts` is the browser side (toolbar: Connect FM-1, Live, Send patch, Store on FM-1); `tools/m1_link.py` does the same from a terminal.

**Parameter inputs and the source matrix (patch format 2, M1-0.6).** Every module except the FM-1 panel and the output has exactly two parameter inputs, `p1` and `p2`, each with an attenuverter (-1..1; scales and inverts), and a matrix with the sources p1, p2, k1, k2, k3, k4 on one axis and the module's parameters on the other. A parameter's effective value is base + (block mean of p1 x att1 and of p2 x att2, for the inputs the matrix assigns to it) x (max - min), clamped. The four knobs k1..k4 are the FM-1's encoders: on the device the SELECT encoder steps through the modules of the patch, and K1..K4 change the parameters their matrix column assigns on the selected module (one click = 1/100 of the range, or the parameter's own step if larger; five times that when turned fast). The FM-1 panel module is the patch's only input and the exception that stays as it was (there is no separate MIDI module: the keys and USB MIDI are handled by the firmware, and by the browser host, and play the one voice that the panel module outputs as pitch, gate and vel; a saved `midi` module becomes the panel module on load): its parameters are k1..k4 themselves and its outputs feed the patch, so with it selected the knobs work as the panel knobs. Default matrix: p1, k1 -> parameter 1, p2, k2 -> parameter 2, k3 -> parameter 3, k4 -> parameter 4. Old (version 1) JSON patches with `<param>_cv` cables are converted on load. The editor shows each card's two inputs with sliders and the matrix as a checkbox grid; changes to the matrix re-send the patch, attenuverters and parameters are live.

**Preset bank (M1-0.8).** The firmware has the 32 factory presets compiled in (`presets.h`, generated from `web/src/presets.ts`). The editor's Presets page lets you choose up to 32 presets (factory ones or the patch in the editor), order them, and upload them: each goes into one flash sector (`slotstore.c`, slots 0..31 at 0xA0000..0xC0000, header with name and CRC written last) through the SLOT / SLOT_ERASE / SLOT_INFO commands, without being loaded. With a non-empty bank the PRESET knob (encoder 6) and MIDI program change step through the occupied slots, otherwise through the compiled-in presets; the top bar shows the preset name. The bank is separate from the current patch of STORE (patchstore.c), which wins at boot.

Not done yet: the FM-1's buttons, a patch name on the device, reading a patch back, the knob matrix columns have no meaning in the browser (there the sliders are the knobs).

## Measured CPU budget (benchmark firmware, `firmware/src/bench.c`)

Per 128-frame block (2902 us of audio), interrupts off, 16 repetitions, 1 us resolution, run on a real FM-1:

| kernel | us/block | instances in 70 % of a block |
|---|---|---|
| osc, Q15 parabolic sine | 7 | 290 |
| 4x Q15 multiply-add | 9 | 225 |
| state variable filter, Q15 | 8 | 253 |
| osc, float | 489 | 4 |
| 4x float multiply-add | 444 | 4 |
| state variable filter, float | 340 | 5 |
| float to int16 per frame | 116 | 17 |

Conclusions: the core has no FPU (float links against `libcompiler-rt.a` soft float) and float is 40 to 70 times slower, so the audio path is **fixed point only** (Q15 samples, 32-bit accumulators, no float, no 64-bit division). Float is acceptable only at control rate (per block), and better avoided. The fixed kernels are tiny; real modules will cost several times their bare kernel (buffer traffic, modulation, CV), so plan for tens of module instances, and measure the real engine before promising more. The 1 us resolution makes the fixed numbers coarse (+-1 us).

## Panel buttons, saved state, LCD (M1-0.9)

- **OCT- / OCT+** (matrix buttons 0 / 1) shift the keys by up to three octaves (the shifted button's LED breathes, faster the further from 0: ±1 slow, ±2 medium, ±3 fast; a message `OCTAVE +1` shows in the top bar); a held key ends the note it started. **SAVE** (button 9) writes the current state to flash: the patch with its edited parameters, the octave, the selected module and the preset index (the unused words of the current-patch header). **HOME** (8) selects the FM-1 panel module and returns from the arpeggiator pages. ARP 10, SEQ 11, LFO 5, PLAY 12 are the arpeggiator pages and transport; FX 2, SEL 3, ENV 4, EDIT 6, GLO 7 and REC 13 are named and unused (no banner). HOME, ARP, SEQ and LFO glow dimly (`fm1_led_dim`). The button ids are Felucca's panel table; only PLAY and REC there were measured on hardware.
- **LCD** (`firmware/src/ui.c`, previewed on the host with `tools/ui_preview.sh OUT.png PRESET [MODULE [OCTAVE [PAGE [ARP_STEP [MENU_TAB [MANUAL_LINE [POLY]]]]]]]`): a top bar with the preset name (black on the accent colour; messages replace it for a moment), a picture of the patch as a vertical strip on the right third (modules as coloured boxes in rows by depth, cables as lines, the selected module framed), the selected module laid out like the arpeggiator pages (small label, value at 1.5x size, value bar per knob row), and the two parameter inputs with their attenuverters and assignments. Choice parameters show their names (SAW, TRIANGLE, S&H), numbers their units (180 HZ, 3.19 OCT) and the value the sound really uses (base plus modulation). With the FM-1 panel selected the rows name where each knob goes (`K1 FILTER CUTOFF`, found from the cables and the target's matrix) and show the knob's position as a bar.

## Reverb, logarithmic cutoff, default knob routing

- **Reverb module**: was Freeverb-style (four damped combs into two allpasses, 12 KB); now the FDN described under "Reverb (FDN)" below, same ports plus `pre` and `mod`.
- **Logarithmic parameters**: `ParamDef.log` (the filter cutoff): parameter inputs, the editor slider and the knobs move it in octaves, so a fraction of the range is a fraction of the octaves (`modulate` in `patch.ts`, `eng_step_param` and the log2 / exp2 tables in `engine.c`).
- **Knobs in the factory presets** (plain `wire(kb, 'k1', module, 'p1')` lines at the end of each preset in `presets.ts`; the module's `add(...)` carries the base value, the matrix and the attenuverter, the panel's `add` the knob start positions): every preset routes K1..K4 from its FM-1 panel module to useful parameters. Rules: K1 is the filter cutoff when there is a filter, K4 the delay mix when there is a delay, K3 the reverb mix when there is a reverb. The panel knobs start at the position that leaves the preset's sound as designed (a test checks this and the rules).

## Polyphony

A patch carries `voices` (1..8, `MAX_VOICES`; the JSON field is absent for mono, byte 3 of the binary header, which was reserved and 0, now holds it: an older firmware plays such a patch mono, the new firmware reads 0 as 1). Nothing else in the patch changes: the voices are implicit, as on the Nord Modular.

**Which modules are per voice** (`voiceSplit` in `web/src/patch.ts`, the same loop in `eng_load`): with more than one voice the FM-1 panel's `pitch`, `gate` and `vel` outputs are per voice (its `k1..k4` are not), and every module reached from them through cables (`p1` / `p2` included) is per voice, except `delay`, `reverb` and `output`, which always run once. A cable from a per-voice output into a shared module carries the **sum of the voices**; a cable from a shared output into a per-voice module reaches every voice. A module nothing per-voice reaches (a free LFO, a noise, a constant) runs once. With one voice nothing is per voice and both engines behave exactly as before (the tests compare the renders).

**Engines.** `engine.ts`: a node has one `Inst` (state, buffers, effective parameters) per voice if per voice, else one; the panel is shared but keeps per-voice `pitch` / `gate` / `vel` buffers (`vout`). `engine.c`: the same split with `inst_t` records in `inst_pool` (in the pool section, `ENG_MAX_INST` 128); a node is `inst0, ninst`, the panel has `nv` instances whose knob outputs share one buffer. Rendering walks the processing order once and runs each node's instances in turn; a shared instance that reads a per-voice output has one summing source per voice. The filter's key tracking follows the pitch of the instance's voice (voice 0 on a shared filter). Both engines: `voices` 1 keeps the held-note stack with last-note priority and legato.

**Voice allocation** (identical in both): a note goes to the voice already holding that key, else to the free voice that has been free the longest, else to the oldest sounding voice. A voice taken over while sounding (`retrig`) outputs one low gate sample at the start of the next block, so its envelopes restart (the ADSR retriggers from its current level). Note off drops the gate of the voice holding that note; nothing is recovered when a stolen note's key is still held.

**Limits on the device.** Signal buffers: 255 (`ENG_NBUF`; 108 in the four-voice build), one per connected output and instance plus one per summed input; instances 128 (`ENG_MAX_INST`; 72 with four voices); in the four-voice build both pools are shared by the voices (see "Voices and the shared pools"), so a patch has all of them only while the other three voices are empty. `eng_load` returns -6 / -7 when a patch does not fit, which the editor reports as a refused patch. `deviceBudget` in `web/src/patchbin.ts` counts the same way against the whole pools and the toolbar shows it (red when too big). A typical note (osc, filter, two envelopes, VCA) takes about 7 buffers and 5 instances, so 8 notes of such a patch fit on an otherwise empty FM-1. CPU: a voice costs the per-voice modules' time; 303 Acid uses 11 % of the audio budget mono, so expect 3 or 4 voices of a patch of that size before the budget is gone. Not measured on the device yet.

**Golden vectors.** `web/scripts/golden.ts` adds `poly-pluck` (4 voices, two envelopes, shared delay, more notes than voices), `poly-shared` (3 voices, a shared LFO into every voice's filter `p1`, shared noise through a per-voice VCA, velocity on `p1`, key tracking, two cables into one per-voice input, shared reverb) and `poly-feedback` (2 voices, a feedback cable inside the voice and a shared delay fed back into every voice's mixer), with their own note events; the C engine agrees with the reference to about 0.1 % rms on all of them.

**Controls.** Editor: a `voices` row on the Main module's card (mono, 2..8) with the FM-1 buffer count next to it (red when the firmware would refuse the patch). Device: on the mixer page (GLO) the ALGORITHM encoder steps the polyphony of the selected voice's patch, shown as `MONO` / `POLY n` in that voice's row; `poly_set` in main.c writes header byte 3 of the voice's patch binary and reloads it with `eng_load` (module state restarts, held notes end); if the pools have no room for that count the old one is reloaded and the bar says `NO ROOM FOR n`. SAVE stores the patch with the count. The Main module's page shows `MAIN  POLY 4`. `tools/ui_preview.sh OUT PRESET MODULE OCTAVE PAGE STEP TAB LINE POLY` previews both (the firmware calls a polyphonic patch's notes "notes" and the four patches "voices", as the panel does).

Not done: the HELLO / INFO reply does not report `ENG_MAX_POLY`; unison / detune.

## FM oscillator

The oscillator has two ways to make FM-style timbres: the `pm` input (phase modulation by another signal, the `pm` parameter is the index in radians per unit of input, 0..8) and the `fb` parameter (operator feedback: the raw wave modulates its own phase, by pi radians per unit of the average of the last two samples at `fb` = 1, the DX7's level 7). Feedback inside the module replaces the one-block-late feedback cable for this purpose.

**FM mode.** When `pm` is connected with an index above 0, or `fb` is above 0, the oscillator runs at twice the sample rate: two waves per frame (the `pm` input interpolated linearly between frames), then a polyphase half-band decimator of four first-order allpass sections, two per path (coefficients Q16 `5376 17567 35764 55599`, flat to 0.22 fs, 41 dB down above 0.28 fs: 19.4 kHz and 24.7 kHz at 44.1 kHz). Sidebands between the old Nyquist and the oversampled one are filtered out instead of folding back; on bright high notes the non-harmonic (aliased) energy drops from -27..-33 dB to about -41 dB, the decimator's floor. Both engines use the same coefficients; the fixed-point one keeps the allpass states in Q16 (`inst_t.s.osc`). Cost: about 2.3 oscillators. The plain path (no pm, no feedback) is unchanged, so patches without FM render exactly as before.

Two things to know when patching: the band-limited signal overshoots the level (up to about 1.4x on very bright settings), so leave headroom before the output; and the feedback loop runs at the oversampled rate, so the sound for a given `fb` is a little brighter than the same number on a 44.1 kHz implementation.

Binary patch format 7: the oscillator record grew by the `fb` parameter.

## Assemblies (editor only)

`web/src/assembly.ts` is the model, `web/src/assemblies.ts` the library page and the factory set (`web/src/assemblies/*.json`), `editor.ts` the canvas side. The patch stays flat: `Patch.assemblies` is an overlay of entries `{ v, id, name, label, x, y, open, modules, inputs, outputs, params }` where `modules` are ids in `patch.modules`, `inputs` / `outputs` are exposed inner ports (`{ module, port, label }`) and `params` promoted inner parameters (`{ module, param, label }`). Cables always join inner ports, so the engine, `voiceSplit`, `encodePatch`, the protocol and the firmware are untouched, and `validatePatch` keeps the field as an unknown one; `fixAssemblies` (called by the editor when a patch comes in) drops entries that do not fit the modules and reports them. Members are plain modules, never the panel or an output, and never in two assemblies; `v` is there so an entry can later name another assembly as a member.

Rules: `reconcile` keeps an assembly consistent after every structural change (departed members leave, every inner port with an outside cable is exposed, labels of ports that stay are kept); `hidePort` refuses while an outside cable uses the port; a module that joins (`addMember`) retracts the exposures that only its cables had caused. A saved assembly (`AssemblyDef`, `format: "modular-1-assembly"`) is a small patch with local ids 1..n, positions from the top left member, the cables between members, exposed ports and promoted parameters, parameter values as defaults, p1 / p2 matrix and attenuverters, and no K1..K4 assignments (also stripped on insert, since knobs belong to the patch). `insertAssembly` gives fresh ids, places the collapsed card at the next free grid slot and refuses past the 32-module cap. The editor keeps a 40-step snapshot undo of the patch JSON for structural changes (Ctrl/Cmd+Z, Shift for redo). On the canvas a collapsed assembly is one card whose port dots carry the inner module ids, so dragging cables works unchanged; an open one is a frame laid out around its member cards, which get the expose / pin toggles, and dropping a card into or out of the frame changes membership.

## Sync, glide, shaper, spread

- `sync` (a gate input) on `osc` and `lfo`: a rising edge through 0.5 sets the phase to 0 before that sample's increment; the previous sample is kept in the state (`s1`). The oscillator honours it in both the plain and the FM path.
- `glide`: `y += k (x - y)` per sample with the ADSR's rate curve (`env_rate`, 99 % in `time`); the fixed-point state is Q24 because in Q16 the step rounds to nothing while the output is still about 1 % short, which on a pitch is audible and broke the golden comparison.
- `shape`: `drive` (1..32, log) into soft (`1.5 x - x^3 / 2` to the knee at 1, then flat), hard (clamp) or fold (triangle of period 4, two's complement masking does the modulo in fixed point), then `level`. The peak is 1 in every mode.
- `spread`: a new per-voice panel output (`VOICE_PORTS`), `(2 v - (n - 1)) / (n - 1)` for voice v of n, 0 for one voice. `port_poly` in the firmware treats it like pitch / gate / vel.
- Binary patch format 8: the two sync inputs moved `p1` / `p2` of osc and lfo, two module types were appended, the panel grew an output. `TYPE_COLOR` in `ui.c` has entries for the new types.


## Level/rate envelope, string, wavetable, chorus

- `env`: four levels and four times, Q30 state like the ADSR. A rising segment adds 2^30 / (r sr) per sample (so 0..1 takes `r`), a falling one approaches at the ADSR's `env_rate` and ends after `r` samples (the last 1 % is stepped so the next segment starts on time). Stages 0 (idle, tracks `l4`), 1..3, 4 (holds `l3`), 5 (release).
- `string`: a delay line of one period with a one-pole (`cl = 1 − 0.9 damp`) in the loop; per block from the block's first pitch: the period (clamped to 2..1102 samples), the loop gain `g = 2^(−log2(1000) · period / (decay · sr))`, and the fractional delay `period − (1 − cl) / cl` (the one-pole's low-frequency delay), read with linear interpolation. A rising gate loads a burst of `round(period)` samples. The loop is clamped to ±2. Firmware: int16 Q13 lines (`str_pool`, 6 × 1104 samples, 13 KB, shared by the four voices) written with first-order error feedback, because the loop would otherwise recirculate the rounding noise with gain 1 / (1 − g); golden `string` matches to 0.04 %.
- `wavetable`: `tools/gen_wavetables.py` defines 32 frames by their first 32 harmonics (cos / sin coefficients, normalized to a peak of 1), writes them as `web/src/wavetables.json` (the reference builds its tables from them at start) and as `firmware/src/wt_tables.h` (int16 Q15, 257 samples per frame, three mip levels of 32 / 16 / 8 harmonics, 49 KB of flash). The mip is chosen per block from the first pitch (32 harmonics below sr / 64, 16 below sr / 32, else 8); frames are read with linear interpolation and crossfaded by `pos`. Phase modulation is the plain oscillator's (not oversampled).
- `chorus`: shared like the delay (`SHARED_TYPES`, `T_CHORUS` in the firmware's voice split); a 927-sample Q13 line, two taps `12 ms ± 8 ms · depth · sin`, the right one a quarter cycle behind, linear interpolation. One instance per patch (`ch_pool`).
- Pool budget: see "Voices and the shared pools" (the numbers of this batch were superseded by the merge with the four-voice firmware).

## Sequencer, clock divider, S&H, quantizer, pulse

- All five act on rising edges through 0.5 (Q16 32768), like `sync`. `seq`: ten parameters (the first module above eight, hence the u16 masks of format 9); `out` is `s[pos]` every sample, so the step's knob is live; the random direction uses the LCG of the LFO's S&H. `clkdiv` counts edges modulo 16 · div (a common multiple of div, 2, 4, 8) and starts at −1 so the first edge is a downbeat. `quant`: semitones = 12 · in − root, octave by floor division, the nearest of the scale's degrees or the next root; ties go down (the two engines can differ at an exact float tie, which modulation never hits). `pulse`: a sample countdown of round(time · sr).
- Golden `seq-clock` (clock -> divider -> pendulum sequencer -> quantizer -> oscillator, sequencer gate -> pulse -> ADSR, d4 -> sync) and `sh-random` (clocked S&H on noise -> pentatonic quantizer, a tracking S&H on the filter, a random sequencer on pulse width; 2 voices) pass at 1.5 % and 0.2 %: the edge decisions line up sample for sample.
## Pan, crossfade, vowel, phaser, digitizer, noise colour

- `pan`: l = in·cos((p+1)π/4), r = in·sin((p+1)π/4) with p = clamp(pan + pos, −1, 1), per sample (C: sin_turn at (p+1)/8 of a turn).
- `xfade`: out = a·(1−m) + b·m, m = clamp(mix + pos, 0, 1).
- `vowel`: three SVF stages (the normalized band output k·v1, peak 1) at the formant frequencies of A (730, 1090, 2440), E (530, 1840, 2480), I (390, 1990, 2550), O (570, 840, 2410), U (440, 1020, 2240) Hz with gains 1, ½, ¼; the position v = clamp(vowel + input[0], 0, 4) interpolates the frequencies linearly between neighbours once per block; k = 1/Q, Q = 2 + 18·res. The C version reuses svf_g / svf_stage and Q20 states like the filter.
- `phaser`: four first-order allpasses y = a(x − y₁) + x₁ with one coefficient a = (g−1)/(g+1), g = tan(πf/sr), f = center·2^(2·depth·tri), tri a triangle LFO at `rate` read once per block; the input of stage 1 is in + fb·(stage 4's previous output), clamped to ±8; out = in·(1−mix) + wet·mix. In C the coefficient is Q24 from one 64-bit division per block.
- `crush`: step 2^(1−bits), y = floor(x/step + ½)·step on the taken sample, held for `rate` samples (C: shift by 17 − bits).
- `noise` `color`: y += c·(white − y), c = 2^(−5·color) (color 0 is c = 1: the old noise bit for bit); the state is Q24 in C.
- Golden kits: `pan-xfade` (3 voices), `vowel-phaser`, `crush-color`.
## Assemblies: merged ports, placement, nesting

- Merged ports: `PortRef.also` (inputs only) lists the further inner inputs a container jack feeds; `targetsOf` / `findRef` resolve them, `mergePorts` / `unmergePort` edit them, `hidePort` treats a group as one and refuses while any target has an outside cable. Cables stay per inner input: the editor creates one per target when a cable lands on the jack (`dot.dataset.also`) and removes the hidden siblings when the drawn one is clicked. Dedupe on the canvas is free: only the primary's dot exists while the assembly is collapsed.
- Placement: `freeSpot(occupied, w, h)` scans `GRID` cells in reading order against the rectangles of the visible cards, containers and frames (the editor measures the DOM, or the model before the first layout).
- Nesting: `AssemblyInst.children` (ids), `allModules` / `descendants` / `parentOf` / `depthOf`, `MAX_DEPTH` 3. `boundary` and `outsideCables` use all modules; a parent's `inputs` / `outputs` / `params` may point at a descendant's module only while the direct child exposes / promotes it (`reconcile` enforces, so `reconcileAll` goes children first and loops until stable). `makeAssembly` nests when the selection is inside one assembly; `addChild` / `removeChild` move an assembly (the editor calls them after a container drag, judged by the card header). `ungroup` lifts members one level, `deleteAssembly` removes direct modules only. Saved files gain `children` and `assemblies` (NestedDef with local ids); `validateAssemblyDef` checks the tree, `fixAssemblies` repairs a loaded overlay (missing children, two parents, loops, depth).

## Unison

- `osc` parameters `unison` (1..5) and `detune` (0..100 cents, default 10): in the plain path (no pm, no feedback) the oscillator runs n phases, voice j detuned by detune·(2j/(n−1) − 1) cents (−detune .. +detune, symmetric), and outputs their sum / n (the peak stays at `level`; detuned copies beat). A sync edge restarts every phase. The FM path ignores unison (one voice). C: the extra phases are `inst_t.s.osc.ph[4]` (the union is sized by the delay's record, so nothing grew), one `exp2_scale` per voice per sample, sum × 1/n from a table. Binary patch format 11 (the oscillator record has 9 parameters). Golden kit `unison` (5 + 2 voices): 1.3 % rel rms (the detuned saw edges fall on different samples in float and Q16, as in the other saw kits).

## Frequency shifter

- `shift`: single sideband. A Hilbert pair (Olli Niemitalo's two chains of four second-order allpasses y = a²(x + y₂) − x₂, coefficients `HILBERT_A` / `HILBERT_B`; chain A's output delayed by one sample is I, chain B's is Q) and a quadrature oscillator at `shift` + cv·cvamt Hz (per block from the block mean of cv): up = I·cos + Q·sin, down = I·cos − Q·sin (the sign convention of this pair; verified by the test: a 440 Hz sine shifted by 100 comes out at 540 on `up`); each output is in·(1 − mix) + shifted·mix. Below about 20 Hz the pair's phase error lets a little of the other sideband through, as with any such design. C: a² in Q30 (`HILB_A2` / `HILB_B2`), each section in the two-state form w = x + a²w₂, y = a²w − w₂ (18 words of state), signals Q16, `sin_turn` for the oscillator, the increment from Hz as (hz << 16) / sr in u32 turns (a negative shift wraps). Golden kit `shift` (saw, LFO on cv): 0.4 % rel rms.

## Pitch bend, mod wheel, aftertouch, CC to knobs

- The Main module has three more outputs, shared by the notes like the knobs: `bend` (−1..1), `mod` (0..1) and `at` (0..1). The `pitch` output already includes the bend at ±2 semitones (`BEND_OCT`), so every patch bends; the raw `bend` output is for other uses. CC 1 is the mod wheel, channel aftertouch (0xD0) the `at` output. CC 16..19 set the Main module's knobs k1..k4 (0..1). Web: `input.ts` parses 0xE0 / 0xB0 / 0xD0 into worklet messages `bend`, `cc`, `at`; `Engine.bend / cc / aftertouch` keep one set of values (`ctl`), copied into every voice at the start of a block (the engine sets the editor's knobs only in the worklet: the sliders do not follow a CC). Firmware: `eng_ctl_v(voice, ENG_CTL_*, q16)`, `E.ctl[]`, filled by `m_fm1` (`port_poly` treats the new outputs as shared); `midi_drain` routes bend, CC 1, CC 16..19 (through `eng_find(T_FM1)`, `eng_set_param` and `m1_patch_param`, so SAVE keeps the knob) and aftertouch to the voices whose channel matches, as notes. Binary patch format unchanged (outputs are not in the record); `MAX_OUT` is 12.

## Comb filter and modal resonator

- `comb`: the string's line (one period of pitch + coarse, 40 Hz lowest, linear interpolation, the damping one-pole's delay taken off the line) with signed feedback `fb` (−0.98..0.98) and no burst: y = clamp(in + fb·lp(y[n − period]), ±2), out = in·(1 − mix) + y·mix. C: `it->s.str` (buf, w, lp, err with the error feedback) and a string-pool line, so `ENG_NSTRING` is shared by strings and combs.
- `modal`: six two-pole resonators y = a·sinθ·x + 2r·cosθ·y₁ − r²·y₂ (impulse response rⁿ·sin(θn): a unit impulse rings at amplitude 1), partial i at ratio (i+1) + struct·(bar_i − (i+1)) with the free bar's ratios 1, 2.756, 5.404, 8.933, 13.34, 18.64; r = 2^(−log2(1000)/(decay_i·sr)) with decay_i = decay/(1 + 2·damp·i); amplitudes (0.3 + 0.7·bright)^i normalised to a sum of 1; partials at or above 0.45 sr are left out; states held to ±8. Coefficients once per block from the block's first pitch. C: g, c1, c2 in Q30, states Q20, rounded products; cos θ must be accurate near 1 (a Q16 cosine moved the pole by 1 % at middle C), so it is 1 − 2·sin²(θ/2) from a Q30 sine lookup (`sin_turn30`); r from `exp2_scale(1 << 30, e)`. Golden kits `comb` (saw, fb −0.85) 0.35 % and `modal` (gated noise burst) 2 % rel rms (the decay's table error shows up late in the ring).

## Granular

- `grain` (shared like the delay: one instance per patch, `SHARED_TYPES`): records `in` into a 1 s line (`GRAIN_SECONDS`; int16 Q13 on the device, `grain_line_t` = 88,392 B with the eight grain records, pool `gr_pool`, `ENG_NGRAIN` 1 in the one-voice build, 0 with four voices: such a patch does not load there). `density` grains per second start from a Q24 accumulator (the reference quantizes its increment to 2^-24 too, so both engines spawn on the same samples), a rising edge on `trig` starts one as well; at most `GRAIN_MAX` 8 play at once, a ninth is dropped. A grain reads `size` s (len samples) at rate 2^(pitch/12) from start = w − back, back = span + min(avail, floor(position·avail) + floor(rnd·spray·0.25 s)), span = floor(len·rate) + 1 (clamped to the line), avail = LEN − 1 − span, rnd from the LCG (seed 0x7f4a7c15; drawn even when no grain is free); so a grain never crosses the write head. Window sin²(πt/len) (C: `sin_turn` over half a turn, `winc` = 2^31/len), linear interpolation, the grains summed unnormalised; out = in·(1 − mix) + grains·mix. `freeze` stops the recording (w stays; the grains keep reading). With spray 0 and a frozen line every grain reads the same segment, so periodic content can cancel between grains: use spray. Golden kit `grain` (gated saw, LFO trig, pitch +7, spray 0.3): 0.5 % rel rms.

## Math and logic

- `math`: a' = a·ka + off, b' = b·kb; outputs add, sub, mul, min, max, abs (of a'), cmp (1 while a' > b'). `logic`: inputs high at or above `thresh`; outputs and, or, xor, not (of a). Both stateless, per sample, Q16 in C. Golden kit `math-logic` (xor of two square LFOs gates an ADSR; max / abs of the math module on a VCA and a pitch).

## Envelope follower and compressor

- `dyn`: inputs `in`, `side`; outputs `out`, `env`. The detector is a one-pole peak follower of |side| (|in| when side is not connected) with the ADSR's rate formula (99 % in `attack` up, `release` down); it rides a little under the peak of a steady tone and ripples at the signal's frequency. Gain above `thresh` (dB): 2^(makeup − slope·(log2 env − log2 thresh)), slope = 1 − 1/ratio; below it only the makeup `gain` (dB). C: env Q24, rates Q30 (`env_rate`), dB → octaves by 1/6.0206 in Q16, one `log2_q16` + `exp2_q16` per sample while above the threshold (`exp2_q16` gives a plain integer: the Q16 / Q24 offsets are added to its argument). Golden kit `dyn` (gated saw into the compressor, its env output on a second VCA): 0.3 % rel rms.

## Macro ranges

- Model: `ModuleInst.range` = `{ p1?: { [param]: [lo, hi] }, p2?: ... }`, ends 0..1 in `paramUnit` space (octaves for a log parameter, no slider bend; `paramValue` is the inverse: the same pair the morph uses). `fixMatrix` keeps a range only on parameters the pin controls (`map`) and clamps the ends; `rangeOf(m, pin, name)`.
- Engines: in applyCv / apply_cv a pin with a range on the parameter sets the base to `paramValue(lo + clamp(v, 0, 1) × (hi − lo))` with v = block mean × attenuverter (replacing the slider's value and the morph), the other pin adds as before (`modulate`, which for a log parameter adds in the bent unit space exactly as it always did, so patches without ranges are bit-identical). C: `range_t E.ranges[ENG_MAX_RANGES]` (48 per voice: module, pin, parameter, lo, hi as u8) and `node_t.ranged[2]` bit masks so the table is only scanned for a ranged destination; `morph_value` maps the u8 ends (× 257 → Q16).
- Binary format 15: header flag bit 1 = a macro range section after the morph B set: u8 count, then 5 bytes per range (module index, pin, parameter index, lo, hi as 0..255). The section is last, so a live edit on the device (`m1_patch_range`: update, append, or remove by moving the last entry into the hole) never shifts the records. Protocol RANGE 0x23 (module, pin, param, on, lo, hi); `eng_set_range` / `eng_range`.
- LCD: `module_row_b` draws a bracket (ticks at both ends, a line between them) over the bar of a knob row whose parameter has a range on p1 or p2. The four-voice instance pool went to 72 for the table.
- Golden kit `macro` (a triangle LFO into the filter's and the ADSR's p1 with ranges in octaves, the ends of the decay swapped; K2 into the oscillator's pulse width): 1.6 % rel rms.

## Patch morphing

- Model: `ModuleInst.paramsB` (the B side's parameters per module, never on the Main module), `Patch.morphName` (display). `sameStructure` (same module types in order, same cables by module index), `setMorphTarget` / `clearMorph` / `hasMorph`, `morphValue(pd, a, b, t)` (choices and toggles snap at 0.5; log parameters interpolate in octaves without the slider's bend; the rest linearly). The Main module gained the parameter `morph` (0..1) and the control input `morph`.
- Engines: the morph position of a block is the Main's `morph` parameter plus the block mean of its morph input, which holds what the input summed in the previous block (one block late, so the LFO can be anywhere in the processing order), clamped to 0..1 (`Engine.morphPosition`, `morph_position` in engine.c). applyCv / apply_cv start from the morphed base instead of the parameter when the patch has a B side and the position is above 0; the modulation then adds as before. The firmware keeps the B side as unit positions (`node_t.parb`, u16 per parameter, octaves for a log parameter: `morph_unit` / `morph_value`), 24 B per node. A cable into the Main's input never makes the Main per voice (`voiceSplit`, and in C the panel already has nv instances); T_GRAIN was missing from the C shared list and is there now.
- Binary format 14: header word 6 (was reserved) bit 0 = a B set follows the cables, one i32 Q16 per parameter of every module in record order (the Main's values are written but ignored). `m1_valid` accounts for it; records keep their offsets, so PARAM / ATT / BYPASS edits are unchanged. Protocol: the morph position is the Main's PARAM (no new command); CC 20 on the device.
- Device: one-voice build: the mixer page's second row `K2 MORPH` (NO B SIDE when the patch has none; `morph_turn` in main.c, `morph_row` in menu.c), CC 20 → FM1_P_MORPH. The four-voice build has no knob for it (CC 20 and the editor only). The four-voice instance pool went from 92 to 80 for `parb` (and to 72 for the macro range table).
- Golden kit `morph`: a subtractive voice with a brighter square B side, an LFO into the Main's morph input, morph 0.3: 2.4 % rel rms (the unit-space rounding of the B side shows in the resonant filter).

## Reverb (FDN)

- `reverb` is an eight-line feedback delay network: line lengths 331 439 547 661 773 881 991 1117 samples (primes, 7.5..25 ms at 44.1 kHz; the TS engine scales them with the sample rate), Householder feedback f_k = t_k − Σt/4 (lossless mixing, so the decay is set by the per-line gains alone), in every line a one-pole damping filter (coefficient damp × 0.8) and a gain g_k = 10^(−3 L_k / (T·sr)) so that every line loses 60 dB in T = 0.2 × 2^(5·size) s (0.2 .. 6.4 s). Input: pre-delay (0..40 ms, `pre`), two diffusion allpasses (223, 347 samples, g 0.5), × 0.125 into every line; wet = Σ raw line outputs × 0.5. Lines 0 and 1 are read with a fractional, linearly interpolated delay that swings by `mod` × 6 samples (sine at 0.5 and 0.83 Hz): the chorusing that keeps fixed lines from ringing. Measured in the test: a sustained noise of 0.5 rms gives a wet level of 0.13 (size 0) .. 0.29 (size 1); the tail of size 0.5 falls 53 dB/s. Memory: 8074 int16 samples = 16 KB per instance (`RV_LEN`; was 12 KB): the one-voice build keeps one, the four-voice build two and gives up 16 signal buffers for them (`ENG_NBUF` 108). C: Q13 lines as before, T and the gains through `exp2_q16`, the modulation through `sin_turn`; golden kit `reverb` 0.1 % rel rms (the C and TS modulators agree to a fraction of a sample over the whole tail).

## Oversampling toggle (shaper, digitizer) and sequencer glide / gate

- `shape` and `crush` have an `os` toggle (patch format 13: new parameters). With it the module runs at 2x: the FM oscillator's polyphase half-band (the same four allpass sections, Q16 coefficients `HB` / `HB_A`) is used as the interpolator (even sub-sample = path 0, odd = path 1, no gain change: the zero-stuffed signal's half-band has gain 2) and again as the decimator, path 1 fed the odd sub-sample of the previous frame as in the oscillator (`os2` in modules.ts; `os_up0` / `os_up1` / `os_down` in engine.c, 17 words of state). Measured in the test: a 5 kHz sine hard-clipped at drive 4: the 5th and 7th harmonics, which fold to 23 and 13 kHz at 48 kHz, drop by 11..12 dB with `os` (what is left is the folding of still higher harmonics at the doubled rate); the fundamental and the 3rd harmonic are unchanged, the rms is 9 % lower (the energy above 22 kHz is gone rather than folded). The digitizer's `rate` keeps counting input samples (the counter runs at 2 x rate). Golden kit `os-shape-crush` (saw into a hard clip into 5 bits / rate 3, both oversampled): 1.2 % rel rms.
- `seq` parameters `glide` and `gate` (fractions, 0..1): the clock period is measured between the last two rising edges (`since` / `period`, nothing until two edges were seen), `glide` is a one-pole on `out` reaching 99 % in glide × period (Q24 state, `env_rate_q8`; 0 = the step itself, bit-exact as before), `gate` holds the gate output for round(gate × period) samples after an edge that lands on a non-rest step (1 = legato; 0 = the clock's own width as before). MAX_PAR is 12. Golden kit `seq-glide`: 0.8 % rel rms.

## Filter: notch, peak, allpass outputs

- `filter` outputs `notch`, `peak`, `ap` appended after `mix` (positions are append-only, so the binary patch format is unchanged). From stage 1's values (v0 = in, v1 = bp, v2 = lp12, k = 2 − 1.98·res): notch = v0 − k·v1 (= lp12 + hp), peak = v2 − hp (= lp12 − hp: unity far from the cutoff, 2/k at it), allpass = v0 − 2k·v1 (= notch − k·bp, |H| = 1). The C version computes them only when one of the three outputs has a cable (`dummy_out` check once per block). Golden kit `filter-notch` (saw, sine LFO on cv, the three outputs mixed): 0.2 % rel rms.

## Ladder filter

- `ladder`: four TPT one-poles (y = G(x − s) + s, s' = y + v with v = G(x − s); G = g/(1+g), g = tan(πfc/sr)) in a loop with k = 4·res. Zero-delay feedback solved linearly per sample: y4 = (G⁴x + S)·F with S = (G³s₁ + G²s₂ + Gs₃ + s₄)(1 − G) and F = 1/(1 + kG⁴); the loop input is then u = sat(drive·x − k·y4) and runs through the stages (the saturator is inside the loop, so at res 1 the self-oscillation limits itself). sat(v) = v − v³/6.75 for |v| ≤ 1.5, ±1 beyond (slope 1 at 0, peak 1). Outputs lp24 (stage 4) and lp12 (stage 2). Parameters cutoff (log, 20..4000 Hz), res, drive (1..8, log), cvamt, track. The coefficients are computed once per block from the block mean of `cv` (× cvamt, + key tracking), unlike the SVF's per-sample update: one `recip24` per block instead of one per sample. No resonance compensation (the passband drops with res, as on the original). C: G, G²..G⁴, F in Q24, states Q20, products rounded; the saturator bounds the states so they need no clamps. Golden kit `ladder` (saw, LFO on cv, res 0.85, drive 3): 0.12 % rel rms.

## Voices and the shared pools (merge of the four-voice firmware 1.0.2 with polyphony and the module batches)

Upstream's 1.0 line made the FM-1 four-timbral: four independent patches, which the panel, the manual and the saved state call **voices** (SEL cycles them, each has its own MIDI channel, arpeggiator, mixer level and accent colour; `eng_t EV[ENG_VOICES]`, `eng_voice_select`). This branch had meanwhile given a patch **polyphony** (`Patch.voices`, 1..8 notes, `voiceSplit`). Both are kept: the firmware runs four patches, each of which may be polyphonic. In the firmware the two are told apart as voices (patches) and notes (`pv_t`, `ENG_MAX_POLY`, `eng_poly`); the JSON field and the editor keep `voices` for the polyphony, since the web app has one patch.

**Memory.** Upstream fitted four engines by giving each a fixed slice (40 buffers, one 521 ms delay, one reverb, 24 modules); this branch needs instance records, string lines, a chorus and more buffers per patch. Fixed slices of that size four times over do not fit in the 408 KB pool, so the big memories are now **pools shared by the voices** (`engine.c`): every slot carries an owner byte (`*_own[]`, 0 = free, else voice + 1). `eng_load` first frees the slots of the voice it loads into, then takes free ones (`slot_take`; instances of one node must be contiguous, `slots_take`); the other voices' slots are untouched (the audio ISR is held off during a load, `m1_apply`). A patch that finds no free slot does not load (-4 lines, -6 buffers, -7 instances; `NO ROOM` on the panel, the voice keeps its old patch). Sizes: 128 signal buffers (64 KB), 96 instances (21 KB), 4 delay lines of 23000 samples (521 ms, 184 KB; the reference engine uses the same length; ping-pong halves it), 2 reverbs (24 KB), 6 strings (13 KB), 1 chorus (1.9 KB), the four `eng_t` (21 KB), the LCD strip (30 KB), the patch copies and staging buffers (33 KB). A stand-in compile (clang for riscv32, `-S`, since the JieLi toolchain is Linux-only) puts the pool at 408 KB of 418 KB; `tools/build.py` has the real number. Per voice: 32 modules, 192 cables, 128 summed inputs, 256 sources, patches up to 3072 bytes (the HELLO reply says 32 / 192 / 4). The editor's `DEVICE` budget (`patchbin.ts`) is the whole pool, i.e. what one patch may use while the other voices are empty.

**Ports.** The Main module's outputs are `pitch gate vel k1..k4 clock spread`: `clock` (upstream, 24 ppqn from the arpeggiator or MIDI clock) is shared by the notes like the knobs, `spread` is per note. The LFO's inputs are `clk` and `reset` (upstream's names; this branch's restart input was called `sync`, which is now the LFO's tempo-sync *parameter*; `validatePatch` renames cables into an LFO `sync` input to `reset`, the factory assemblies were regenerated). The oscillator and the wavetable keep their `sync` input. Binary patch format 10.

**Panel.** GLO is the mixer (upstream); the polyphony control that sat on this branch's GLO page is the mixer's ALGORITHM encoder (`poly_set`), shown per voice in the mixer rows and in the Main page title (`MAIN  POLY 4`). The manual (`manual.c`) lists the shared limits.

**The voice count is a build switch.** `ENG_VOICES` (engine.h) is 1 unless the build says otherwise (`M1_VOICES=4 python3 tools/build.py`, `-DENG_VOICES=4` for the host tests and previews; `tools/golden.sh`, `tools/arp_test.sh` and `tools/ui_preview.sh` take `M1_VOICES`). The one-voice build is the one this fork plays: one patch, polyphonic, with the pool to itself. The four-voice code stays, so upstream merges do not have to be redone: the panel files derive from the count (`ENG_VOICE_INIT(a, b, c, d)` builds a per-voice initialiser; SEL, the voice number in the top bar, the mixer rows and mute keys, the `Vn CHANNEL` rows (`CH_TAB`, the menu walks a tab's rows by membership, `menu_row_at`), the loading screen's lines and the manual's text follow it; `arp_any_play()` replaces the four-term test for the clock source). Pool sizes per build: one voice 255 buffers, 128 instances, 1 delay, 1 reverb, 8 strings, 1 chorus (stand-in compile: 302 KB of 418 KB, 115 KB free, of which the planned 1 s granular buffer takes 88 KB); four voices 108 / 72 / 4 / 2 / 6 / 1 and no granular line (409 KB; 128 / 96 until the shifter's state and the Main module's three new outputs widened the instance record). The HELLO reply carries the modules / cables / delay counts of the build; the editor's `DEVICE` budget is the one-voice build's. The saved-state record keeps four voice slots (`BLOB_NV`) in both builds: a one-voice build writes voice 1 and empty slots (default arp, channel, level) and reads the first slot of a four-voice record, so a stored state moves between the builds.

## Bypass (module on / off)

Every module except Main and Output has a bypass switch, the way a device in a DAW rack can be turned off. A bypassed module does not run (its state is kept, so it resumes where it stopped when turned on again) and its outputs carry its **through input**: `ModuleDef.thru`, by default the input called `in` (filter, ladder, delay, reverb, chorus, shaper, digitizer, phaser, vowel, glide, comb, modal, shifter, compressor, granular, S&H, quantizer); the mixer passes `in1`, the crossfade `a`, the pan copies `in` to both `l` and `r`. A module without a through input (oscillators, LFOs, envelopes, noise, sequencer, string, math, logic, pulse, clock divider) is muted: silence on every output. Input sums still run, so a bypassed module inside a feedback loop keeps the graph consistent.

- Model: `ModuleInst.bypass` (patch.ts, dropped on Main / Output by `validatePatch`), `thruInput(def)`. Binary format 12: bit 7 of a record's type byte (the record size is unchanged); `ENG_PATCH_VERSION` 12.
- Engines: `Engine.run` copies or clears the outputs (`Engine.setBypass` for the live switch, worklet message `bypass`); engine.c `m_bypass` instead of `process()` (`node_t.bypass`, `eng_set_bypass` / `eng_bypass`, `def_t.thru` from export-defs).
- Protocol: `22 BYPASS module u8, on u8` (protocol.ts, proto.c `m1_patch_bypass` keeps the stored copy in step so SAVE / STORE keep it).
- Editor: the ⏻ button in the card header (the body dims, undo works); `EditorEvents.onBypass`. Assemblies have no switch of their own: bypass the members.
- FM-1: the FX button toggles the selected module (message `FILTER OFF` / `FILTER ON`, `NOT ON THIS MODULE` for Main and Output); the module page title ends in `OFF` and the patch picture draws the module grey.

## Parameter ranges and steps (audit)

- The editor's logarithmic sliders rounded their value to a whole number (`Math.round` after `fromUnit`), so a glide time, envelope rate, chorus or phaser rate, drive, grain size or decay could only take 0, 1, 2 ... They now snap to the parameter's `step` (`snapTo` in editor.ts); the LCD knobs were not affected (`eng_step_param` works in octave units).
- Filter and Ladder `cutoff` open to 16 kHz (was 4 kHz; the tan table allows 0.45 of the sample rate). The modulation range is 9.6 octaves now instead of 7.6, so a parameter input on the cutoff moves it a bit further per unit; the Pluck preset's K1 start was recomputed.
- LFO `rate` (0.02..40 Hz) and the ADSR's `a`, `d`, `r` are logarithmic like the Env L/R rates and Glide: the slider and the knobs give the short times room, modulation moves them in ratios.
- The Delay's `time` goes 1..520 ms, the length of its line (`DELAY_TIME_MIN/MAX` in modules.ts; it went to 1000 and was clamped); the synced note lengths are spread over that range (stored synced values pick a different length than before).

**Assemblies.** The ⏻ on an assembly card or frame (`bypassAssembly` in assembly.ts) bypasses every member, nested ones too, and remembers in `AssemblyInst.kept` which members were already off on their own; switching the group back on restores exactly that. A nested group's own switch is superseded while the parent is off. `toDef` writes the members' own switches into a saved definition, not the group's. Editor only, like the rest of the overlay.
